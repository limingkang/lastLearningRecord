# 大模型 API 和 Prompt 工程

这个阶段开始真正接入模型。你的目标不是只会调一个聊天接口，而是能把模型能力封装成可复用、可测试、可维护的业务服务。

## 学习目标

- 掌握主流 LLM API 调用方式
- 能写稳定的 Prompt
- 能使用结构化输出
- 能实现 Function Calling 和 Tool Calling
- 能处理失败重试、限流和成本统计

## 模型 API 基础

建议至少熟练一种模型供应商，再了解多模型兼容方案。

可以学习：

- OpenAI
- Claude
- Gemini
- DeepSeek
- 通义千问
- 智谱 GLM

需要掌握：

- Chat Completions 或 Responses API
- Messages 格式
- System 指令
- 流式输出
- JSON 输出
- 错误码处理
- 速率限制

## Prompt 基础

Prompt 不是一句玄学提示词，而是任务说明书。

常见结构：

```text
角色：你是谁
目标：要完成什么
上下文：已知信息
约束：不能做什么
输出格式：必须如何返回
示例：给出正确样例
```

## 结构化输出

AI 应用不要长期依赖纯文本解析。你需要让模型输出 JSON，并用 schema 校验。

适合结构化输出的场景：

- 简历分析结果
- 商品分析报告
- 合同风险条款
- 客服质检标签
- Agent 下一步动作

## Function Calling

Function Calling 让模型决定什么时候调用你定义的函数。

示例工具：

- 查询天气
- 查询订单
- 查询知识库
- 计算利润
- 生成标题
- 保存日报

学习重点：

- tool schema 设计
- 参数校验
- 工具返回结果格式
- 多轮工具调用
- 工具失败兜底

## Prompt 版本管理

项目变大后，Prompt 也需要管理。

建议：

- 每个 Prompt 单独成文件
- 记录版本号
- 写清楚输入输出
- 保存测试样例
- 修改后跑回归测试

## 成本和稳定性

必须学习：

- token 统计
- 请求重试
- 超时控制
- fallback 模型
- 缓存相同请求
- 敏感信息脱敏

## 推荐实践

做一个“AI 简历优化助手”：

- 用户输入简历和目标岗位
- 模型输出匹配度
- 给出技能缺口
- 改写项目经历
- 输出 JSON
- 前端用 Vue 展示结构化结果

- 工具调用失败怎么办
- 如何控制 token 成本
- 如何防止模型胡乱调用工具
