# RAG 知识库开发

RAG 是最容易落地、也最容易出作品集的方向。很多企业并不需要训练模型，而是需要把内部文档、业务知识、客服资料接到大模型上。

## 学习目标

- 能实现文档上传和解析
- 能完成文本切分和向量化
- 能使用向量数据库检索内容
- 能让回答带引用来源
- 能减少幻觉并处理无答案场景

## 文档解析

需要支持的文件类型：

- Markdown
- TXT
- PDF
- Word
- HTML

学习重点：

- 提取纯文本
- 保留标题层级
- 保留页码或段落位置
- 清理无效内容
- 保存原始文件信息

## 文本切分

Chunk 切分会直接影响检索效果。

需要理解：

- chunk size
- chunk overlap
- 按标题切分
- 按段落切分
- 按 token 切分
- 元数据 metadata

常见 metadata：

- 文件名
- 页码
- 标题
- 段落序号
- 上传时间
- 用户 ID

## Embedding

Embedding 是把文本转换成向量。

重点学习：

- 文本向量是什么
- 相似度搜索是什么
- query embedding 和 document embedding 的区别
- embedding 模型如何选择
- 向量维度和成本

## 向量数据库

入门选择：

- Chroma
- FAISS
- pgvector

求职项目建议用 PostgreSQL + pgvector，因为它更贴近真实业务系统。

需要掌握：

- 向量入库
- top_k 检索
- metadata 过滤
- 删除和更新索引
- 多用户数据隔离

## 检索增强回答

基础流程：

1. 用户提问
2. 问题向量化
3. 向量数据库召回相关 chunk
4. 把 chunk 放入 prompt
5. 模型基于上下文回答
6. 返回引用来源

## 幻觉控制

必须加上的规则：

- 只基于检索内容回答
- 找不到答案就明确说明
- 每个关键结论带来源
- 不允许编造页码和文件名
- 显示召回片段给用户核对

## 推荐实践

做一个“个人知识库 RAG 助手”：

- Vue 上传文档
- Node.js 解析文档
- 生成 embedding
- 存入向量数据库
- 用户提问
- 返回答案和引用来源
