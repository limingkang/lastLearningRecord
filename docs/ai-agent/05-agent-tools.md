# Agent 工具调用和工作流

这个阶段要把 AI 从“问答系统”升级成“任务执行系统”。Agent 的关键不是会聊天，而是能在安全边界内调用工具完成目标。

## 学习目标

- 能设计 Agent 可调用工具
- 能实现多步骤任务执行
- 能保存 Agent 运行状态
- 能处理工具失败和人工确认
- 能搭建业务型 Agent 项目

## 工具设计

工具就是 Agent 能调用的能力。

常见工具：

- 搜索知识库
- 查询数据库
- 调用第三方 API
- 计算价格和利润
- 生成文件
- 发送通知
- 保存任务结果

一个工具需要包含：

- name
- description
- input schema
- output schema
- 权限要求
- 错误返回

## Agent 执行循环

基础流程：

1. 接收用户目标
2. 分析是否需要工具
3. 选择工具
4. 生成工具参数
5. 执行工具
6. 读取工具结果
7. 决定继续调用工具或输出答案

## 任务状态管理

Agent 执行可能不止一轮，所以需要保存状态。

需要保存：

- task id
- user goal
- current step
- tool calls
- intermediate results
- final result
- error message
- created time

## Workflow 和 Agent 结合

很多真实项目不是完全自由 Agent，而是“固定流程 + 局部智能”。

例如电商选品：

1. 读取商品信息
2. 分析成本
3. 计算利润
4. 生成标题
5. 生成卖点
6. 判断是否建议上架

每一步固定，但具体分析交给 LLM。

## 人工确认

危险操作不能让 Agent 直接执行。

需要人工确认的操作：

- 删除数据
- 发送邮件
- 提交订单
- 修改线上配置
- 调用付费接口

前端要提供确认界面，后端要保存确认记录。

## 多 Agent 协作

入门阶段不建议过度复杂，但需要理解基本模式。

常见角色：

- Planner：拆解任务
- Researcher：收集资料
- Analyst：分析数据
- Writer：生成报告
- Reviewer：检查结果

## 推荐实践

做一个“电商选品 Agent”：

- 输入商品信息
- 查询竞品数据
- 计算利润率
- 生成标题和卖点
- 输出是否建议上架
- 保存分析报告

## 面试要能回答

- Agent 工具 schema 怎么设计
- 如何避免 Agent 乱调用工具
- 工具调用失败怎么办
- 什么场景需要人工确认
- Agent 和 Workflow 怎么结合
- 多 Agent 是否一定比单 Agent 好
