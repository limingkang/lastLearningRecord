# 工程化、评估和安全

这个阶段决定你的项目是“能跑的 Demo”，还是“像真实业务系统的作品”。AI Agent 岗位面试时，面试官通常不只问你怎么调模型，还会问你怎么评估效果、怎么排查问题、怎么控制成本、怎么防止危险操作。

## 学习目标

- 能给 RAG 和 Agent 做基础评估
- 能记录模型调用、工具调用和任务链路
- 能实现权限、限流、脱敏和人工确认
- 能部署 Vue + NestJS + FastAPI 项目
- 能让项目具备可维护性和面试说服力

## RAG 评估

RAG 不只是能回答，还要知道回答质量如何。

重点指标：

- 召回是否命中正确文档
- 答案是否基于引用内容
- 引用来源是否真实
- 没有答案时是否拒答
- 用户问题改写后是否还能命中

推荐准备一个测试集：

- 20 个文档内有答案的问题
- 10 个文档内没有答案的问题
- 10 个需要跨段落综合的问题
- 5 个故意诱导模型胡编的问题

## Agent 评估

Agent 评估重点不是文采，而是任务是否完成。

需要观察：

- 是否选择了正确工具
- 工具参数是否正确
- 是否处理了工具失败
- 是否在危险操作前等待确认
- 最终结果是否符合业务目标
- 执行步骤是否可追溯

可以为每个 Agent 任务保存：

- 用户目标
- planning 结果
- tool calls
- tool results
- final answer
- success / failed
- error reason

## Trace 和日志

AI 应用必须能排查链路。

建议每次请求生成一个 `traceId`，贯穿：

- 前端请求
- NestJS 接口
- FastAPI 服务
- LLM 调用
- 向量检索
- 工具调用
- Agent 任务状态

需要记录：

- 模型名称
- prompt 版本
- token 用量
- 调用耗时
- 错误码
- 工具参数
- 工具返回摘要

## 成本控制

AI 应用天然有调用成本。

需要实现：

- 用户级调用次数限制
- 单次上下文长度限制
- token 用量统计
- 大模型调用缓存
- 低成本模型 fallback
- 文档索引异步执行
- 长任务排队执行

## 安全和权限

Agent 会调用工具，所以必须加边界。

重点能力：

- API Key 只放后端
- 用户数据隔离
- 文件上传类型限制
- 敏感信息脱敏
- Prompt Injection 防护
- 工具白名单
- 写操作人工确认
- 管理员操作审计

危险工具示例：

- 删除文件
- 写数据库
- 发送消息
- 提交订单
- 调用付费接口

这些工具必须要求二次确认，并保存确认记录。

## 测试

至少补齐这些测试：

- NestJS Service 单元测试
- API 集成测试
- Prompt 回归测试
- RAG 测试集评估
- Agent 工具调用测试
- 前端核心交互测试

AI 输出不稳定，所以测试重点不是逐字匹配，而是检查结构、字段、引用、工具调用和业务结果。

## 部署

推荐部署结构：

```text
Vue 静态站点
NestJS API 服务
FastAPI AI 服务
PostgreSQL + pgvector
Redis
对象存储
```

需要掌握：

- Dockerfile
- docker-compose
- 环境变量
- 数据库迁移
- 日志查看
- 健康检查
- CI/CD 自动构建

## 推荐实践

把前面的 RAG 项目升级成工程化版本：

- Vue 前端
- NestJS 主后端
- FastAPI RAG 服务
- PostgreSQL + pgvector
- Redis + BullMQ
- Docker Compose 一键启动
- traceId 链路日志
- token 成本统计
- RAG 测试集评估脚本

## 面试要能回答

- 你的 RAG 项目怎么评估效果
- Agent 调错工具怎么办
- 如何排查一次回答很慢的问题
- 如何防止 Prompt Injection
- 如何控制 token 成本
- 如何设计人工确认机制
- NestJS 和 FastAPI 如何协作
- 线上部署需要哪些服务
